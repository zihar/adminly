# Filter UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Per-column **filter controls** on `ResourceTable`, URL-synced (nuqs), driving server-side filtering — declared via the existing `def.list.filters`. Closes CRUD spec §6 (the plumbing exists; only the UI + store filtering are missing).

**Architecture:** For each field in `def.list.filters` (a `string[]`), `ResourceTable` renders a filter control (a `<select>` from the field's `def.form.fields[field].options`, or an async-select via its `optionsFrom`), bound to nuqs URL state and merged into the `listParams.filters` object already consumed by `useList` (and export). The mock `collection-store` + the `items` route apply `filter[field]` server-side. `buildListSearchParams` already serializes `filter[k]=v` and `ListParams.filters` already exists — no data-layer type changes.

**Tech Stack:** React 19, nuqs, TanStack Query, shadcn Base UI, Vitest + @testing-library/react, Playwright.

## Context / Decisions
- **Filter options come from the field's form meta**: for filter field `X`, use `def.form.fields[X]` — if it has static `options` → `<select>` with those (labels are already-resolved strings); if it has `optionsFrom` → async-select (fetch via that resource's `useOptions`). (Workflow-status-as-filter would need `workflow.statuses` as the source — out of v1 scope; note it.)
- **Demo**: `items` declares `list.filters: ["prioritas"]` (the static `select` field already on the items form) → a working filter dropdown.
- **URL-synced** per-field via nuqs (bookmarkable, consistent with page/sort/q); empty value = no filter (dropped from params). An "All" option clears a filter.
- Export already builds from `listParams` → it will honor active filters automatically.
- Generic; i18n mirrored en/id (`common.all` + reuse field `labelKey`); Base UI; no `any`; `@/` alias.

## Global Constraints
- Reuse: nuqs `useQueryStates` (already in `resource-table.tsx` for page/q/sort/order), `def.form.fields[field]` meta, `async-select-field`'s `useOptions` pattern for async filters, `createCollectionStore`, `resolveLabel`/`useI18n`. `npx tsc --noEmit`+`npm run lint` clean; tests verify real behavior (real MSW request carries `filter[...]`); route handlers unchanged pattern.
- Rules-of-hooks: build the nuqs state config from `def.list.filters` (stable per resource) at top level; do not call hooks per-filter inside a `.map` unless via a stable child component.

### Task 1: Backend — store + items route honor `filter[]`
**Files:** `src/app/api/_store/collection-store.ts`; `src/app/api/items/route.ts`; `src/config/resources/items.ts` (declare `list.filters`); tests (`_store/__tests__/collection-store.test.ts`, `items/__tests__/items-route.test.ts`).
**Produces:** `collection-store.list` accepts `filters?: Record<string, unknown>` and returns only rows where, for every entry, `String(row[k]) === String(v)` (skip empty/undefined values). `items` route reads all `filter[<field>]` query params into a `filters` object and passes it. `itemsResource.list.filters = ["prioritas"]`.
- [ ] Step 1 (RED): store test — `list({ filters: { prioritas: "high" } })` returns only rows with `prioritas === "high"`; empty/absent filter → all rows; combined with `q`/`sort` still works. Route test — `GET /api/items?filter[prioritas]=high` returns only matching rows.
- [ ] Step 2: implement — `collection-store.list` filter step (after `q`, before sort): for each `[k,v]` in `filters` where `v !== "" && v != null`, keep rows where `String(row[k]) === String(v)`. `items/route.ts`: `const filters: Record<string,string> = {}; for (const [k,v] of sp.entries()) { const m = k.match(/^filter\[(.+)\]$/); if (m) filters[m[1]] = v; }` then pass `filters` to `itemsStore.list({...})`. Add `list.filters: ["prioritas"]` to `itemsResource` (keep existing `list` config).
- [ ] Step 3: `npm test`, `npx tsc --noEmit && npm run lint`. Commit `"Filter: collection-store + items route hormati filter[] + items.list.filters"`.
